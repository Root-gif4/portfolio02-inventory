# 01 要件定義書

## 1. 背景と目的

小さなお店や社内では、在庫を Excel で管理していることが多い。次のような困りごとがある。

- 入出庫のたびに在庫数を手で書き換えるため、数字がずれる。いつずれたか分からない
- 間違いを直すときに数字を上書きすると、何があったか分からなくなる
- 在庫切れに気づくのが遅れる

本システムは、**入出庫の記録から在庫を計算する** ことでずれをなくし、在庫切れ・発注の必要をすぐ分かるようにする。

## 2. 利用者と使い方

| 利用者 | すること |
| --- | --- |
| 店舗・事務の担当者（1 人〜数人、同じ PC） | 入庫・出庫の登録、在庫の確認、取消 |
| 管理者（店長など） | 商品・カテゴリの登録、集計の確認、CSV の取り込み、バックアップ、整合性チェック |

- 1 台の Windows PC で使う。ブラウザで画面を開くが、データはその PC の中だけに保存する
- ログインはしない（PC にログインできる人が使う前提）

## 3. 機能要件

| No | 機能 | 内容 |
| --- | --- | --- |
| F1 | 商品マスタ管理 | 追加・変更・使用停止／再開。コード（英数字 20 文字以内）は重複不可。取引のある商品はコードを変えられない。削除はしない |
| F2 | カテゴリ管理 | 追加・名前の変更・使用停止／再開。使用中の商品があるカテゴリは停止不可 |
| F3 | 入庫・出庫管理 | 入庫・出庫・棚卸調整を登録。数量・日付・取引先・メモ |
| F4 | 在庫数の自動計算 | 在庫＝取引の増減の合計。任意の日の在庫も出せる |
| F5 | 在庫不足アラート | 在庫 0 以下＝在庫切れ、発注点以下＝要発注。ダッシュボードとメニュー横に件数 |
| F6 | 取引履歴・検索 | 期間・カテゴリ・商品・種類・キーワードで検索。取引の取消（逆向きの取引を追加） |
| F7 | 月別入出庫集計 | 月ごとの入庫数・出庫数・棚卸調整・差引・金額。グラフと CSV |
| F8 | CSV インポート・エクスポート | 商品・入出庫を取り込み（確認 → 取り込む、全部正しいときだけ保存）。商品・在庫・取引を書き出し |
| F9 | データ整合性チェック | 8 項目（DB の壊れ、つながり、取引の向き、取消の対応、在庫のマイナス、未来の日付、停止商品の在庫、停止カテゴリ） |
| F10 | バックアップ | 画面・コマンドから DB の写しを作る（30 世代） |
| F11 | ダッシュボード | 数字のカード、要対応の商品、グラフ、最近の取引 |

## 4. 業務ルール

| No | ルール |
| --- | --- |
| R1 | 在庫数は保存せず、取引の増減の合計で求める |
| R2 | どの日の終わりにも在庫がマイナスにならない。過去の日付の取引も、その後の在庫まで確かめる |
| R3 | 確定した取引は書き換え・削除しない。取消は、元と同じ日付・種類で増減が逆の取引を追加する。1 つの取引は 1 回だけ。取消の取引は取り消せない |
| R4 | 未来の日付の取引は登録できない。数量は 1〜1,000,000 の整数 |
| R5 | 使用停止の商品は入出庫できない。在庫が 0 でないと使用停止にできない |
| R6 | 棚卸調整は「数えた数」を入れ、その日の在庫との差を記録する（差が 0 なら登録しない） |
| R7 | CSV の取り込みは 1 行でも誤りがあれば何も保存しない |

## 5. 非機能要件

| 項目 | 内容 |
| --- | --- |
| 使いやすさ | 画面・メッセージはすべて日本語。各ページに「何をする画面か」を表示。登録前に登録後の在庫を見せる。ライト／ダーク |
| 正しさ | 業務ルールは処理本体（service）と DB の制約の両方で守る |
| 安全性 | この PC からだけ接続できる。CSV の数式インジェクション対策。想定外のエラーで内部情報を出さない |
| 性能 | 商品 1,000・取引 10 万件程度で画面が数秒以内 |
| 保守性 | 画面と業務の処理を分ける。DB アクセスは service に集める。自動テスト |
| データ保全 | バックアップ、整合性チェック、ログ（1MB×5 世代） |
| 費用 | 無料のソフトだけ |

## 6. 対象外

- ログイン・権限（Portfolio 03 で扱う）
- 複数の倉庫・ロケーション、ロット・賞味期限、発注書の作成
- 別の PC やスマホからの利用
