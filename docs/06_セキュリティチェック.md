# 06 セキュリティチェック（20 項目）

実施日：2026-11-23。本システムは **この PC の中だけで動く Web アプリ**（ログイン・外部通信・AI 機能なし、DB は SQLite）。
使っていない仕組みの項目は「該当なし」とし、同じ役割のもので確かめた。

| No | 項目 | 結果 | 確認内容 |
| --- | --- | --- | --- |
| 1 | コードに API キー・パスワードがない | 〇 | 鍵・パスワードを使う処理がない。コードを検索して確認 |
| 2 | .env が .gitignore に入っている | 〇 | `.gitignore` に `.env`・`.venv/`・`data/`（DB・ログ・バックアップ） |
| 3 | Git の履歴に鍵が残っていない | 該当なし | まだ Git に登録していない（鍵もない） |
| 4 | 画面側のコードに隠すべき鍵がない | 〇 | 鍵がない。画面に出すのは商品・取引のデータだけ |
| 5 | Supabase の RLS | 該当なし | 使わない。代わりに：DB ファイルは PC の中だけ（`data/`）、外から接続する仕組みがない |
| 6 | Firebase のルール | 該当なし | 使わない |
| 7 | 他の人のデータを読めない | 該当なし | ログインなし・1 台の PC で使う。代わりに：サーバーは `127.0.0.1` だけで待ち受け、ほかの PC からつながらない（`netstat` で確認） |
| 8 | URL の番号で他人のページが開けない | 該当なし | 利用者ごとのデータがない。URL はページの名前だけ |
| 9 | 管理者ページ | 該当なし | 権限の区別がない（要件定義書の対象外）。PC にログインできる人が使う前提 |
| 10 | SQL インジェクション | 〇 | SQL はすべて SQLAlchemy の組み立て（値はプレースホルダ）。文字列で組む SQL は固定の PRAGMA だけ。検索のキーワードは `%` `_` をエスケープ（UT-15） |
| 11 | XSS | 〇 | `unsafe_allow_html` を使わない（Streamlit は HTML をそのまま出さない）。CSV の書き出しは数式インジェクション対策（UT-17。テストで不具合を見つけて修正） |
| 12 | サーバー側でも入力チェック | 〇 | 画面の制限（数量の最小値など）とは別に、`service.py` で全項目を確かめ、DB の CHECK・UNIQUE・外部キーでも守る（UT-02・08・13） |
| 13 | ファイルの種類と大きさ | 〇 | 取り込みは `.csv` だけ・5MB・10,000 行まで、バイナリ（NUL）は拒否（UT-19）。Streamlit の `maxUploadSize = 5` |
| 14 | パスワードのハッシュ | 該当なし | パスワードを扱わない |
| 15 | エラーで内部情報を出さない | 〇 | 想定外のエラーは受付番号だけを表示し、詳細はログへ（IT-07）。`showErrorDetails = "none"` |
| 16 | ライブラリの弱点・古い版 | 〇 | pip-audit（requirements-dev.txt とその依存すべて）で既知の脆弱性なし。版は requirements で固定 |
| 17 | AI の回数・上限 | 該当なし | AI 機能なし |
| 18 | プロンプトインジェクション | 該当なし | AI 機能なし |
| 19 | システムプロンプトに秘密 | 該当なし | AI 機能なし |
| 20 | /security-review | 該当なし | まだ Git のブランチ・変更差分がないため実行できない。代わりに上の観点でコードを確認。GitHub に登録したら実行する |

そのほかの配慮：

- 利用状況の送信（`gatherUsageStats`）をオフ。Streamlit の右上メニューから開発者向けの項目を隠した（`toolbarMode = "viewer"`）
- 確定した取引は書き換え・削除せず、取消も記録に残る（あとから何があったか追える）
- バックアップと整合性チェックで、データの壊れ・書き換えに気づけるようにした
- 見本データ・samples の CSV の会社名・商品はすべて架空
