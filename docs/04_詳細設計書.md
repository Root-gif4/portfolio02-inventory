## 2. 入力の整え・チェック（service）

| 関数 | 内容 |
| --- | --- |
| `clean_text` | NFKC（全角英数→半角）、前後の空白を除く、必須・文字数・制御文字 |
| `clean_code` | 上に加え大文字にし、全角のダッシュを `-` に。`^[A-Z0-9][A-Z0-9_-]{0,19}$` |
| `clean_int` | 「1,200」「１２」「1200円」を受け付ける。小数・真偽値・範囲外はエラー |
| `clean_date` | `date`・`datetime`・「2026-11-23」「2026/11/23」。2000-01-01〜今日 |

## 3. 在庫がマイナスにならないことの確認（R2）

`_ensure_never_negative(product, delta, txn_date)`：在庫を減らす取引（delta < 0）のときだけ行う。

1. その商品の取引を `(txn_date, id)` の順に読む
2. 新しい取引を「その日の既存の取引のあと」に入れる
3. 先頭から足していき、**各日の終わり** の在庫が txn_date 以降で 0 未満になる最初の日を探す
4. 見つかったら、txn_date の当日なら「在庫が足りません（今 a 個、b 個減らすと c 個）」、
   後の日なら「〇日の時点では足りますが、そのあとの出庫があるため △日に在庫が c 個になります」

「日の終わり」で判定するので、同じ日に出庫 → 入庫の順で登録しても断らない。
書き込みは `BEGIN IMMEDIATE` で始まるので、確認から INSERT までの間に別の書き込みが割り込まない。

## 4. 取引の登録

| 関数 | kind | quantity | delta | 補足 |
| --- | --- | --- | --- | --- |
| `record_in` | IN | 入力 | +quantity | |
| `record_out` | OUT | 入力 | −quantity | R2 を確認 |
| `record_adjust(counted)` | ADJUST | \|差\| | counted − その日の在庫 | 差 0 はエラー。減るときは R2 |
| `reverse_transaction(id)` | 元と同じ | 元と同じ | −元の delta | 日付も元と同じ。取消済み・取消の取消はエラー。減るときは R2 |

使用停止の商品・存在しない商品はエラー。

## 5. 一覧・集計

- `stock_table(as_of)`：商品と `SUM(delta)`（as_of 以前）、最終取引日を結合。在庫金額＝在庫数×仕入単価。状態＝`stock_status`
- `stock_status`：使用停止 → 「使用停止」、在庫 ≤ 0 → 「在庫切れ」、在庫 ≤ 発注点 → 「要発注」、それ以外 →「適正」
- `alerts`：在庫切れと要発注。在庫切れを先に、そのあと「発注点 − 在庫」が大きい順
- `search_transactions(TxnFilter)`：条件を AND。キーワードは商品コード・商品名・取引先・メモの部分一致（`%` `_` はエスケープして文字として探す）。新しい順に最大 5,000 件。状態は「取消」（取消の取引）／「取消済み」（取り消された取引）
- `monthly_summary`：`strftime('%Y-%m')` で月ごとに、入庫数＝IN の delta の合計、出庫数＝OUT の −delta の合計（取消は元と同じ月なので差し引かれる）、棚卸調整、差引、金額（数量×今の仕入単価）

## 6. CSV

| 項目 | 内容 |
| --- | --- |
| 文字コード | UTF-8（BOM あり・なし）→ Shift_JIS の順に試す |
| 上限 | 5MB・10,000 行。NUL を含むファイルは拒否。空行は読み飛ばす |
| 見出し | 必須の列がない・同じ見出しが 2 つ → 中止 |
| 商品 | 商品コード（必須）・商品名（必須）・カテゴリ（必須）・単位・仕入単価・発注点・メモ。同じコードは上書き、ないカテゴリは作る。ファイル内のコードの重複はエラー |
| 入出庫 | 取引日・種類（入庫／出庫）・商品コード・数量（必須）・取引先・メモ。上の行から順に登録し、R2 も確かめる |
| 全部か無しか | SAVEPOINT の中で 1 行ずつ登録し、誤りは（行番号, 理由）に集める。確認モード、または誤りが 1 つでもあれば SAVEPOINT を取り消す |
| 書き出し | BOM 付き UTF-8・CRLF。数値でない列の値の先頭が `= + - @ タブ 改行` なら `'` を付ける（`-500` などの数字は除く） |

画面では、確認したファイルの SHA-256 を覚えておき、同じファイルのときだけ「取り込む」を出す。取り込むときも同じチェックを最初からやり直す。

## 7. 整合性チェック

| 項目 | 方法 |
| --- | --- |
| DB ファイルの壊れ | `PRAGMA integrity_check` |
| つながりの切れ | `PRAGMA foreign_key_check` |
| 取引の向き | 取消でない取引の kind・quantity・delta の関係 |
| 取消の対応 | 元と同じ商品・種類・日付、delta が逆、取消の取消がない |
| 在庫のマイナス | 商品ごとに日付順に足し、日の終わりに 0 未満がないか |
| 未来の日付 | txn_date > 今日 |
| 使用停止の商品の在庫 | 停止中の商品の在庫が 0 か |
| 使用停止のカテゴリ | 停止中のカテゴリに使用中の商品がないか |

## 8. 画面（Streamlit）の作り

- `st.navigation` で左のメニューをグループ分け。各ページは上から下へ実行され、操作のたびに作り直される
- 書き込みは `run_action(処理, 完了メッセージ)`：`db()` の中で処理 → 成功なら完了メッセージを次の表示に渡して `st.rerun()`。`InventoryError` は理由を表示、それ以外は受付番号を表示してログに記録
- DB の接続（エンジン）は `st.cache_resource` で 1 つだけ作る
- 入庫・出庫の登録画面は、ボタンより前に「登録後の在庫」を計算し、マイナスならボタンを押せなくする（最終的な判断は service）
- 設定（`.streamlit/config.toml`）：`headless = true`（初回のメールアドレスの質問で止まらないように。ブラウザは start.bat が 5 秒後に開く）、`address = 127.0.0.1`、`maxUploadSize = 5`、`showErrorDetails = "none"`、`toolbarMode = "viewer"`、利用状況の送信オフ、ライト／ダークの色
